# 架构图确定性布局契约 v2

此契约只适用于架构图主图。时序图和独立链路图继续使用既有布局规则；架构图的流程下钻仍使用关系图的边缘端口和正交连线算法。

## 输入结构

- 架构主图必须以 `layout.contractVersion: 2` 启用本契约。缺少版本标记或不符合契约时校验、布局与渲染都失败，不允许回退到旧版模块级连线布局。`template` 可显式指定 A/B/C/D，也可由 `layout.projectKind`、`pipelineGroups`、`kernelGroups`、`deploymentZones` 推导。
- 每层包含 `standardType` 和项目真实的展示名。治理层设置 `crossCutting: true`，并映射为 `governance`。
- `mainChain` 是 1–7 个节点 ID，渲染在图顶部并在对应卡片显示序号；它不是模块调用边的替代证据。
- `layerFlows` 是有证据的展示泳道间关系，主图 `edges` 必须为空，布局边只能是 `layerFlow`。A/C/D 每对相邻泳道最多一条并按展示顺序连接；B 只允许离线与在线管线之间一条关系，可向上或向下。
- 不同数据库、缓存、向量库、对象存储、外部服务继续拆为独立节点。主图不画节点到节点的关系；具体读写、调用和异步边放在下钻图或专图。

## 模板选择

| 模板 | 适用信号 | 结构 |
|---|---|---|
| A 分层泳道 | 有请求入口、服务模块、存储层的应用；默认模板 | 标准层纵向排列，治理列位于右侧 |
| B 双管线 | 代码证据显示离线构建与在线服务两条管线 | 离线、在线两条独立泳道，以一条有证据的汇合边连接 |
| C 内核与扩展 | SDK、框架或库项目 | 公共 API、核心内核、适配扩展、开发工具按证据选择展示 |
| D 部署分区 | 部署配置能证明独立网络/运行分区 | 按部署区域展示，分区归属和分区流向必须有证据 |

信号冲突时先审阅 IR；仍无法判定则采用 A 并把理由写入审阅报告。C/D 的可视分组只是版式结构，不得伪装为源码中的运行时层。

## 固定版面与排布

- 画布宽度固定 1440px；最小正文字号 12px；层标题 16px、卡片标题 14px、说明 12px。卡片高度固定 64px，整图卡片宽度统一，由普通内容区可用宽度和最大列数计算；宽度低于 180px 时拒绝布局。
- 背景 `#F8FAFC`。接入、编排、能力、业务、数据、治理分别使用固定浅色填充/边框映射；扩展与部署区域用中性色。只显示实际出现的类别并绘制图例。
- 每层 1 个模块时单卡居中；2–5 个一排居中；6–10 个平衡分两排；11 个以上必须提供每个节点的 1–4 字职责分组，布局器按组排布。每排独立居中，组框与卡片均不能重叠。
- 主图最多显示 6 条普通泳道。普通层达到 7 条时，IR 必须提供基于职责边界的相邻层合并、依据和证据。治理侧栏最多一列，节点纵向均布并标注“贯穿所有层”。
- 卡片名最多 10 字并且单行；说明最多 12 字；超长内容由结构阶段改写，渲染器不得折行或截断。
- 初始布局是纯确定性函数：同一 IR、同一字体度量和同一模板应产生相同位置。自动布局不使用随机数，不接受模型生成的 x/y 坐标。手动拖动保存的位置是用户编辑状态，并须重新通过几何审计。

## 主图流向与主链路

- 主链路用图顶端的 `主链路：①… → ②…` 文字及卡片序号表示，最多 7 个节点。它不得被误解成所有代码调用的完整关系网。
- 主图连线只表达相邻展示泳道之间有源码证据的层间关系。A/C/D 每对相邻泳道最多一条，B 两条管线间最多一条。连线从泳道底边中心到下一泳道顶边中心；反向双管线边从下方泳道顶边到上方泳道底边。
- 主图连线不锚定卡片、不画模块关系网、不使用虚线、不显示文字标签；图例统一标记为“层间连接”。箭头只占层间通道，不穿卡片或泳道标题/副标题。
- 每条主图路径必须是连接相邻两条泳道边界中点的一段直线。除边界端点外，路径须全在两泳道之间；任何模块级根边、越层边、重复层对边或偏离通道中点的边均阻断渲染。交互根图直接复用该 V2 SVG，不能通过旧交互路由另画一套箭头。
- 下钻关系图保存模块间证据边，最多 8 条；时序图仍按消息顺序向下，返回箭头等既有时序语义不变。

## 分图类型的箭头样式

- 架构主图的泳道层间连接使用 3.6px 线宽、18×14px 实心三角头；其他图（下钻、流程、时序）使用 1.8px 线宽、12×10px 实心三角头。箭杆路径停在三角底边，三角尖端与原关系目标端点对齐。
- SVG marker 使用 `markerUnits="userSpaceOnUse"`，主图与其他图按样式类别、线色分别定义 marker，并以 `refX="0"` 锚定三角底边。箭杆使用 `stroke-linecap="butt"` 并在底边收口，不得穿过三角头或从尖端露出；箭头填充色必须与所属连线的 `stroke` 完全一致；图例复用相同 marker 与线宽语义。缩放和浏览器窗口不改变画布坐标中的箭头尺寸。
- 治理关系是模块到模块的真实有向边：端点吸附治理模块与被约束模块的边缘，使用虚线和标准实心箭头；拖动任一端模块时按边组路由规则重算。不得用泳道边界装饰线替代关系边。
- `quality_report` 解析渲染后的 SVG，检查两类 marker 尺寸、样式类别、方向属性、尖端与路径终点对齐、平头箭杆以及 marker/线颜色一致性；治理边也必须有箭头。

## 审计与失败策略

- `validate_diagram` 检查 schema、模块数、文字长度、证据、层合并、分组覆盖、模板结构和流向端点。
- `content_density_report` 输出模块/泳道数量、字号、画布宽度和宽高比、证据完整度、硬检查以及软警告。每层 3–5 个为软目标；孤立模块会提示复核。
- `quality_report` 检查节点重叠、文字宽度、卡片等宽、每排对齐/居中、图边是否穿越节点/标题、方向、画布边界和图例颜色对比度。主图只接受 `layerFlows`；每条线必须连接相邻泳道边界，并完全留在两层之间的通道内。任何进入泳道区域、卡片或标题/副标题的线都判失败。主图图宽必须为 1440px、宽高比 1.2–1.8、卡片宽度唯一；颜色文本对比度至少 4.5:1。
- 质量失败不得生成最终图。结构审阅必须在用户明确确认前停止；审阅报告可以计算布局和机器质量，但不得生成 SVG/HTML/PNG。
- 不为通过审计而缩小字号、卡片或阈值；空间不足时返回结构阶段分组、聚合或拆图。项目职责不能被证据支持的合并时，保留独立结构并报告失败原因。
