# 连线边组布局与验收

此规则用于流程类下钻图和独立链路图。架构主图继续遵循泳道契约：主图只连接相邻泳道边界的预留通道，不锚定卡片，也不绘制模块关系网。

## 路由模式

布局前先按端点拓扑识别边组，拖动后仍按同一边组整体重算路径：

| 模式 | 判定 | 固定绘制方式 | 箭头与标签 |
|---|---|---|---|
| 一对一 | 单条关系 | 端口出发，经正交通道进入目标端口 | 线端箭头；标签紧贴所属线段 |
| 扇出 | 同一来源连接多个目标 | 来源共用出口和主干；3 条及以上且两泳道之间有无遮挡通道时，总线固定在通道中点，各目标从总线分支；其余情况使用局部总线 | 每个目标一枚箭头；3 条及以上时隐藏线标签，把用途放在来源卡片固定标签位 |
| 扇入 | 多个来源连接同一目标 | 来源支线汇入总线；3 条及以上且两泳道之间有无遮挡通道时，总线固定在通道中点，随后只接入目标一次；其余情况使用局部总线 | 汇入目标仅一枚箭头；3 条及以上时用途分别放在来源卡片固定标签位 |
| 双向 | 两节点互相调用 | 去程和返回使用分离轨道 | 两个方向各自有箭头；返回关系使用虚线并由图例解释 |
| 多对多 | 多来源与多目标交织 | 不生成交叉路径，自动呈现关系矩阵 | 矩阵保留每条关系的端点与用途 |

扇出/扇入分支间距至少 12px。共享总线必须连续覆盖所有分支接入坐标；共线点压缩只能移除位于相邻点之间的中间点，不能删掉造成路径反向的极值点。边组有 3 条及以上关系时，线路上不得放逐边标签。来源卡片保持 68px 高：说明占一行、用途标签最多两行；文字无法放入时，布局失败并要求精简或拆图，不截断、不增高卡片。

分支拓扑和总线路由是稳定契约，箭头系统修复不得改变其端口、主干、总线、分支坐标、分支间距或标签策略。扇出每个目标各有一个箭头；扇入的来源线只进入总线，总线到目标仅有一个箭头。边组实线、虚线和颜色必须与对应图例一致。

箭头头部按图类型分两档：架构主图层间连接使用 3.6px 线宽和 18×14px 实心三角头；下钻、流程、时序等其他图使用 1.8px 线宽和 12×10px 实心三角头。marker 均使用 `markerUnits="userSpaceOnUse"`，以 `refX="0"` 锚定三角底边；箭杆路径终点必须落在三角底边，三角尖端从底边向前延伸到原目标端点。禁止箭杆进入三角头或从尖端露出；`stroke-linecap="butt"` 保证箭杆在底边干净收口。填充色必须等于所属线的描边色，图例复用相同 marker。`quality_report` 从最终 SVG 检查尺寸、类别、箭杆底边、尖端位置、颜色和箭头引用，不通过时阻断输出。

`kind="governance"` 表示有方向的模块关系，不是泳道装饰线。连线必须从真实源模块路由至真实目标模块，保持治理虚线样式、补齐同色实心箭头；静态布局与浏览器拖动重路由都使用同一组端点和边组路由规则。扇入、扇出、双向的既有总线端口和分支几何不因箭头样式调整而改变。

扇入/扇出边组中的关系类型必须参与样式计算。纯治理边组的分支、总线和汇入目标箭头统一使用治理色虚线；扇入来源支线不显示箭头，只有总线指向目标的箭头头部。普通调用边组继续使用中性分支色。混合类型边组的共享总线使用中性色，各条关系支线保留各自类型样式；图例须同时列出实际出现的治理线与普通分支线。

当关系图按 LR 横向跨层时，共享竖向总线必须落在来源泳道右边界与目标泳道左边界之间的几何中点；TB 纵向布局则使用两泳道边界间的中点。层间没有正通道或通道被其他泳道占据时，不强行套用该位置，改用局部总线。拖动重路由复用同一判定；几何审计核对总线、主干和每条分支是否落在约定位置。

## 机器审计

`quality_report(..., hardcoded_ports=True)` 检查边组分类、共享主干/总线及其对每条分支的连续覆盖、边缘中点端口、正交线段、分支间距、箭头数、标签到所属线的距离、来源用途标签和卡片文字槽位。它同时检查卡片重叠、线交叉、文字溢出、连线穿越无关节点及图例样式。任一硬错误都会使审计失败。

架构主图的层间箭头是另一类受限关系：路径必须是一段直线，横坐标取相邻泳道水平中点，纵坐标止于两泳道边界；路径不得进入任一泳道。因此不会经过泳道内的卡片、标题或副标题。`quality_report` 会拒绝非层间边、非相邻泳道、偏离中点或进入泳道的路径。

## 回归与浏览器验收

合成压力用例在 `tests/layout_fixtures/`，覆盖 2/3/5 路扇出、7 路扇入、3×3 多对多、双向关系和长标签。运行：

```powershell
python -m pytest -q tests/test_branch_routing.py tests/test_layout_contract.py tests/test_layout_render.py
```

浏览器脚本直接截取交互页内的 SVG，并在独立上下文中验证拖动后边组重路由；截图不是从 SVG 另建页面生成。`tests/browser_consistency.py` 覆盖 Chromium/Edge、`file://`/本地 HTTP、fresh/stale/invalid 存储状态和多个窗口宽度。矩阵驱动器支持按协议执行子集，以便在本机策略禁止回环访问时单独验证 `file://`；未运行的组合不得记为通过。

Playwright 若无法连接本地 HTTP 回环地址，应明确记录该环境限制；仍可用 `file://` 交互页检查与真实截图验证，不能将未运行的 HTTP 组合标记为通过。
